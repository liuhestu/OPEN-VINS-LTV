# B4 online score contract

B4 is one preregistered causal mechanism test after B3 failed the unchanged 5% gain criterion on V2_03. It is not a numeric threshold search or an ON implementation.

The provider is camera0, which the actual Observer correction consumes. Before processing the current transaction, compute the current LTV and strong past-only geometry predictions and freeze the point's old-quality gate. Evaluate the two camera0 predictions against the current bearing solely to stage a score for the next packet. Current and future target angles cannot alter the already frozen current gate. Both camera0 and camera1 quality evaluation rows use that one camera0 point gate; they do not form separate fusion measurements.

Commit the staged score only after successful Observer correction actually consumed that camera0 feature ID. A committed receipt includes physical time, epoch, global tracker ID, core ID, entered-time generation, both model angles, provider camera0, and consumption status. Snapshot transaction failure, non-finite prediction, missing camera0, retirement/reset or identity change invalidate the score. The next packet requires exactly the previous complete camera packet's score and a matching `(epoch, feature_id, core_id, entered)`; no older last-known score is substituted.

The historical feature log emits `corrected_ids` only when the frame is available, raw-current and has camera Euler substeps, using manager observations with camera0. Offline B4 joins that actual-consumption ledger with prediction source identities and their strict timestamp ordering. It does not assume that merely observing a bearing proves Observer consumption. The metadata does not establish physical-point truth or independent noise.

If B4 admits, the online implementation must perform this same strong-geometry fit and receipt commit under the estimator's before/after transaction hooks. Offline CSV scores are not an online API. The strong geometry uses existing seed fitting on past camera0 observations only, strictly excluding the current packet, and frozen native poses/calibration. Its compute cost, memory, point-supply loss and failed transactions must be measured with matched OFF diagnostics. Approximate fusion remains separately OFF by default and will disclose shared seed/main/Observer/visual input and unknown cross blocks. Predictive admission cannot establish main-state benefit or statistical consistency.
