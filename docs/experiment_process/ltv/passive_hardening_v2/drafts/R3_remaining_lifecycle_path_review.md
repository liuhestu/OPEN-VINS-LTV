# R3 剩余候选额度：生命周期与状态保持的证据复核

**当前没有足够具体的证据支持再登记一个同机制候选。** 剩余额度本身不是提出新策略的理由。本结论是现有授权路径的证据判断，不是证明所有生命周期设计都不可能有效；是否判定授权路径耗尽由主线程决定。

只读范围：已保存270/271供给诊断、293完整shadow审计、`LtvAdapterHardened.cpp`、`LtvLandmarkManager.cpp` 和已恢复e792f41的Readiness；未改策略、未生成新ready掩码、未跑仿真。

## 尚未证实的局部容量线索

271保留了一个有限线索：current中的414包pool不足，278包observed<15、136包仅成熟不足；37包池占满30，26包存在当前可见且last_seen为当前的capacity候选。此前302包是包含陈旧reason的统计错误，已撤回，不应复用。

26包只证明局部准入竞争存在，没有证明保留了不合法或错误的记录，也没有证明这些候选可替代当前coasting点并在原成熟等待、once-per-ID和30状态上限下形成连续5s。源码正常coasting仍占状态容量，但其存在是原生命周期合同的一部分，不等于资源泄漏。更早退coasting会不可逆地丢掉可能很快重现的ID及交叉状态；更晚退又会占用容量。没有逐事件因果证据时，二者都是新取舍，不能把选择方向伪装成bugfix。当前不据这26包登记候选，也不降低mature要求、提高状态容量或重复seed。

同样，`pauseHardened`的reset和下一epoch初始化应按其真实输入不可用原因审查，不能仅看到重启函数就推定错误清状态。现有长合法pool窗口内部的失败不需要这些reset即可出现；目前没有定位到“输入仍合法且状态健康，却由错误pause切断潜在成功窗口”的具体事件。静态看到可疑分支不构成改变其语义的证据。

## 结论与停止边界

现有证据支持保留R3已完成的受约束状态保持和资源语义修复；不支持为剩余额度强行再发明生命周期候选。R3B和R3C shadow在固定全域合同下仍NOT_MET，不能用新增ready子集、两处反例未放行或总体精度尚好替代连续5s失败。

逐点共享修正加法分解仍可作为只读根因诊断，但它不是删点反事实，更不自动产生同机制候选授权。若没有新的具体合法输入/状态错误转换反例，下一步改变健康阈值、成熟数、seedGate、观测剔除或另起机制，都超出本次“剩余同机制缺陷修复”的有据路径；应明确报告尚未达标和当前有证据路径不足，而非换名开启第四轮。
