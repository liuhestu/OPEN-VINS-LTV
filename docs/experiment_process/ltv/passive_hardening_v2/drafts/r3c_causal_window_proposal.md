# R3C proposal: causal shared-correction budget (not registered or implemented)

Evidence before proposal: R3B261/265 still fails joint5s; exact cached prediction276 and independent277/284 allow signed correction diagnostics. Corrected fixed-window analysis282 shows accumulated shared v corrections remain below0.364m/s over a fixed1s in both predeclared stable-pool windows, while individual correction rates reach2.21/3.45m/s². Point analysis278/285 finds mostly minority angular mismatches in those windows, but several large shared corrections have no point angle above0.02. No visible mature point was actively evicted. These observations justify testing whether instantaneous activity is an unsuitable proxy for persistent state instability; they do not prove readiness or causal benefit.

This is a proposed availability candidate within the current R3 lifecycle/readiness round. It is **not a bugfix**, nor a change to the scientific error/coverage/recovery contract. It replaces the observed quantity used by the soft health checks, while leaving the observer state/P, C0 gains, admitted points and original main VIO unchanged. Independent review must decide whether this is a genuinely distinct justified candidate rather than a disguised sweep of R3B grace duration. If not, do not register it. No hypothetical ready masks, parameter scan or full run has been used to choose this specification.

## Fixed proposed statistic and guards

Use the already diagnosed1.0s physical interval `(t-1,t]`, once, without a window sweep. For each accepted correction store actual signed `[delta_v,delta_eta]`, original increment norms, the original pre-correction angle P95 and its preceding physical interval. Propagate past shared corrections with the actual executed Euler6x6 transition, including eta-to-v coupling. No P_L probability claim or main-VIO v/g input is involved.

For each branch expose three distinct quantities: norm of accumulated signed correction, sum of norms of individual transported corrections, and maximum original instantaneous increment norm. Divide the first two by the fixed1s duration. Do not cancel the activity or impulse guards when computing the signed net. Compute the angle statistic as a physical-duration-weighted mean of actual per-event P95 values over the same complete interval, with edge intervals clipped to the actual window and no invented intermediate bearing. This is a new temporal statistic, **not** the old instantaneous P95 and not a pooled feature quantile.

Fixed original threshold values are reused with explicit units:

- G: net eta correction rate<=1m/s³, total eta activity rate<=2m/s³, maximum original eta increment<=1m/s².
- V: the same G conditions plus net v correction rate<=0.5m/s², total v activity rate<=1m/s², maximum original v increment<=0.5m/s.
- Shared angle: weighted mean P95<=0.02rad; current instantaneous P95<=0.04rad remains an immediate outer guard.

The activity multiplier2 is fixed, reused as a design choice from the previous exit envelope, without any inherited conservativeness or accuracy guarantee; it is not fitted per sequence. Increment caps are the original rate budgets multiplied by the fixed1s horizon. These caps deliberately allow some instantaneous rate excursions rejected by R3/R3B, so old safety results cannot be inherited. They do not bound true estimation error.

All original current/finite/physical input, geometry, >=15 observed and mature points, >=20 actual corrections, correction-diagnostic validity, physical gravity norm and R3 state-norm guards remain. Every accepted frame must satisfy these hard conditions to contribute to a complete window. Bootstrap, epoch, physical gap, noncurrent or a hard-condition failure clears temporal evidence and the relevant confirmation counters. Missing or unsupported transition data rejects readiness. No stale delta or frame is replayed after recovery.

Require a complete valid physical1s window **and then the original20 consecutive qualifying camera events** before declaring a branch ready. Window filling itself is neither qualifying nor a hard failure: do not clear the accumulating history during fill. At regular20Hz, the earliest possible readiness is about1.95s after the first hard-valid anchor. Ordinary net/activity/weighted-angle checks that fail only revoke the affected branch and reset its confirmation count; retain the actual sliding history. The current instantaneous P95>0.04 is a shared hard failure and clears both branches and their common history; V-specific window failure must not clear G history or confirmation. A failed branch check immediately revokes it; thus no grace latch, extension of grace length, softened confirmation count or reuse of failed R3B state exists. G/V remain separate; G does not require small finite v activity. Preserve original instantaneous diagnostics alongside new metrics. The estimator never receives GT, future labels, sequence name or offline episode masks.

Bound history to64 camera updates (at most fixed arrays/scalars per entry); if full-window history cannot fit at a supported input cadence, reject with an explicit capacity reason instead of silently dropping required evidence. Do not allocate unbounded history. Disabled mode must preserve full old state/P/slots/events and cache bytes.

## Required discriminating tests before a full development run

- Direct causal perturbation propagation, noncommuting substep order, eta-to-v coupling and body-coordinate rotation invariance.
- Nonzero camera/IMU offset, large timestamps, precise interval clipping, irregular accepted cadence, exactly1s history boundary and no future samples.
- Same-signed corrections fail net; large cancelling corrections fail activity/impulse; a small net alone never qualifies.
- Hard faults/empty or immature pool/current outer-angle failure revoke immediately, clear history and require a new full history plus20 confirmations.
- G/V independence, duplicate idempotence, no confirmation increment on acknowledgements, capacity and reset bounds.
- OFF complete state/P/slot/event parity; new window logging and no-logging parity; legacy original scalar fields unchanged.

If review accepts the mechanism and round accounting, register one fixed candidate before creating any ready masks or outcome evaluation. Run the already declared V2_03 development first; retain a failure without adjusting the window/bounds/confirmation to force5s. Only a passing candidate proceeds to the other development and negative/recovery checks and potentially the unopened final confirmation. This proposal does not authorize a fourth mechanism round or additional gain search.

## Exact state and boundary contract before registration

One common bounded evidence history holds actual corrections and angle intervals. G/V have separate confirmation counters; their data are not separately erased on ordinary branch failures. G window-budget failure also makes V fail because V includes G budgets. A V-only failure resets only V confirmation. Maximum-original-increment failure is an ordinary rolling branch-budget failure: revoke that branch immediately and retain the actual history (and offending sample) until it physically leaves the window. It does not reset the observer, throw away adverse evidence or erase the other branch. Shared hard failures alone clear the common history and both counters.

After reset/hard failure, the first subsequent hard-valid event is a new anchor at its physical IMU target. Store its correction with zero angle support before this anchor; never fill the preceding invalid interval. A frame qualifies as a complete history only if `target-anchor >= 1.0` with recorded double physical times, no added epsilon. At exactly1.0s the window may qualify. The prior20-event confirmation then starts: the first complete and budget-passing frame counts1; the twentieth consecutive such frame is ready. Duplicate/nonincreasing events return rejected output without mutating history or counters; bootstrap acknowledgements cannot add a frame.

For current physical target t, let L=t-1.0. An actual correction delta at s contributes exactly iff `L < s <= t`; delta is not fractionally scaled. An angle sample recorded at event b describes the discrete right-endpoint diagnostic on its actual preceding interval(a,b], with a clipped up to the valid segment anchor. Its weight is `max(0, min(b,t)-max(a,L))`. The mean is `sum(weight*P95)/sum(weight)`; complete coverage requires a contiguous actual event-interval union covering[L,t], not an invented hold through missing/invalid data. No P95 is interpolated. Weights are computed by interval differences; accumulation uses compensated or extended-precision summation, and any floating tolerance for verifying the sum must be bounded by arithmetic error only and cannot admit an uncovered physical interval. Online accepted irregular cadence up to the existing0.20s physical gap is allowed; scientific episode evaluation still uses the unchanged pre-existing gap convention.

Each retained entry owns its interval start/end, so deleting entries with end<=L cannot lose a boundary-crossing interval belonging to the next entry. Prune fully obsolete entries before insertion. With64 entries still required, a65th required entry causes shared hard rejection with an explicit capacity reason and resets history; never evict necessary evidence and call the window complete. This numerical resource bound is part of the input contract, not a quality improvement.

Transition data are versioned and tied to observer epoch, actual previous cursor and current target. Phi is the ordered product from the previous actual post-camera state to the current pre-camera state; actual Delta is read directly across the current camera correction. Missing propagation steps, nonfinite values, unsupported epoch or inconsistent interval identity invalidate the window. Disabled mode computes no such extra transitions and must retain old behavior/bytes.
