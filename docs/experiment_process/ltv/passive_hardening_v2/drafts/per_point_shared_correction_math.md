# 实际校正的逐点共享贡献：只读数学审查

审查源码：`ov_msckf/src/ltv/ltv_observer.cpp` 的 `updateFeatures` 校正子循环（约第378–408行）及 `LtvAdapterHardened.cpp` 的 pre/post snapshot。未改算法、未跑仿真。

## 可复原的量

相机事件先完成保留/删除/出生均值写入，再构造按 slot 排序的观测矩阵。对点 i，令 `b_i=R_BC*normalize(bearing_C)`，`Π_i=I-b_i b_i^T`，H_i 为完整状态宽度、只在点 i 对应块含 Π_i 的3行矩阵，`y_i=Π_i p_BC`。核心投影创新是 `r_i,s=y_i-H_i x_s`，单位为米；不是单位视线差或角度。

相机子步 s 使用同一旧状态 x_s 和旧协方差 P_s，H/y 在整帧冻结。q为实际 `q_landmark`，h为 `camera_dt / camera_substeps`。共享状态选择矩阵 S 取状态末尾 `[v;eta]` 六维。定义

`d_i,s = h q S P_s H_i^T r_i,s`，`d_i = sum_s d_i,s`。

于是，在实数算术下 `sum_i d_i = S(x_after - x_before_correction)`，因为每个子步完整均值增量按观测三行块线性相加，再跨子步望远镜求和。这是**实际已执行轨迹上的加法分解**。相机子流不推进物理时间，无需额外 IMU 坐标输运来对同一相机事件的这些项求和。

要匹配真正执行路径，必须每步更新全部 x/P、保留全部交叉块，使用核心原始子步数和旧值求导，协方差更新后执行相同 sanitize；后续贡献使用实际经过谱保护的 P_s。不能把 P 固定为相机开头值，也不能把全部子步创新固定成初始创新。浮点下分块求和改变加法顺序，不能要求 bitwise 等于 Eigen 整矩阵乘法；须报告绝对/相对复原残差。若数值保护触发 reset 或整个事务拒绝，该帧不能作为成功校正贡献分解，应单独标记失败。

Adapter 的 predicted snapshot 位于生命周期处理之前，而核心 correction-before 位于生命周期之后。因此还应核对前后共有 v/eta 本身未被生命周期/seed改写；正常保留/删除/仅点均值 seed 合同满足这一点。贡献侧仍必须使用生命周期处理**之后**的点均值和P布局；新出生点也参与校正，不能仅因为其未进Adapter原P95而漏掉。

## 不能据此声称的量

`d_i` 不等于“删掉点 i 后最终输出改变多少”。删点会改变 H、Ricatti 更新、下一子步 P/x/所有点创新，甚至自适应子步数；若真正删除状态，还会改变 slot、维数、出生/保留历史及后续生命周期。即便人为固定原 P_s 和 h，删除输入项以后剩余点的创新也应随新状态更新，通常不等于直接从真实最终状态减去 d_i。

因此可报告实际共享Δ的向量份额、方向一致/抵消和贡献集中度；贡献范数不是误差，角大也不保证共享贡献大（它还乘射线尺度与共享交叉增益）。若要评估真正删除点收益，需要另行授权、定义删“本帧观测”还是删“状态身份”、执行完整受控反事实，并保留其新身份与预算，不能把加法分解冒充该实验。用GT比较贡献方向也只能是事后诊断，不成为在线删点条件。
