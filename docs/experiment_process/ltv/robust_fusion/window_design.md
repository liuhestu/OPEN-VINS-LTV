# 滑窗非线性方案的实现边界（设计，未实施）

当前 OpenVINS 已有滑窗 clone，但 `State::_clones_IMU` 是 `PoseJPL`，保存姿态/位置，没有每个历史帧的速度。保留 clone 并不等于已有 VINS 的非线性滑窗后端。

真正比较“非线性窗口优化是否使 LTV 有用”至少需要以下独立条件：

1. 定义窗口变量：各帧姿态/位置/速度及 bias，必要的固定标定；原始 IMU 和视觉约束或严格等价的边缘化信息。仅向当前 EKF 添加过去的几个速度数值不是此方案。
2. 每个 LTV snapshot 拥有唯一 measurement ID，只进一次概率模型。优化器重复求解同一模型允许重线性化；把每次优化输出再次作为独立测量注入 EKF，会重复计算已经存在的信息。
3. 明确窗口先验如何形成和边缘化、规范自由度如何保持、何处采用 FEJ。不能一边使用已经融合历史 LTV 的 EKF posterior 作先验，一边重新加入这些 LTV 因子。
4. OpenVINS clone 的精确增广可产生奇异协方差。若构造联合先验因子，必须保留确定约束或使用经验证的秩分解，不能人为加对角量掩盖问题。
5. 因子图应独立输出轨迹用于比较；未经交叉协方差处理，不把其结果喂回同源 EKF。基线图和加 LTV 的图必须共享视觉/IMU模型、窗口、边缘化和初始化，仅改变辅助因子。
6. 验收包括有限差分、规范零空间、无LTV基线、边缘化连续性、同一因子无重复、数值稳定及相同输入支持。此后才比较全EuRoC ATE。

本轮已实现的 Huber 是一次冻结权重的线性化联合 EKF：它是 Huber 目标的 IRLS 一步近似，未求解完整非线性最小值；条件于权重计算的 EKF covariance 也不是鲁棒估计器的无条件真实误差协方差。因此即便得到改善，也不称“已复刻 VINS 融合”。

当前先完成门控/Huber对照。滑窗架构范围已向用户提问；没有回答时采用分阶段方案，不能把未实施的滑窗列入本轮实验结果。

## 门控与Huber的相互作用

当前V质量门控要求 `||r_v|| <= 0.5 m/s`。组合候选最小sigma为0.5 m/s，因此在本轮冻结prior上白化范数≤1，小于Huber delta=2：**组合候选的V分支理论上不会触发Huber降权**。这应由实际日志复核，而不是把QH与Q的相同结果误称鲁棒优化收益。

VINS先筛选snapshot再在窗口里迭代优化，迭代中的状态和残差可以变化，因此初始门控通过并不保证每次求解时Huber都不生效。这是一次IRLS EKF与非线性窗口不能混同的另一原因。
