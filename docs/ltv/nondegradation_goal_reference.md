# OpenVINS + LTV：接入不退化验证与下一阶段执行合同

> 给 Codex /goal 的参考文档。目标是获得可复核的工程结论和明确的下一步，不预设融合必然有效。
> 本文基于用户提供的阶段报告；执行前必须核对本地提交、源码、配置和原始证据。报告摘要不是已经重新验证的事实。
> 数学背景可参考同目录的 ltv_openvins_formulas.md；仓库已有设计合同及源码具有实现层面的约束力。

## 1. 总目标与“为什么做”

将 OpenVINS + LTV 整理为一个可维护、可验证的辅助估计系统，回答：

1. 保留 LTV 管理与 Observer、关闭所有辅助融合时，原始 OpenVINS 是否保持原行为？
2. 开启已有 G/V 更新时，是否在预先规定的测试范围内满足工程不退化？
3. LTV 输出是否提供原始视觉/IMU之外的有效增量信息，而不是重复使用已有信息？
4. Landmark 进入 ON 前，是否具备可实施的统计模型和接入条件？
5. 如果融合暂时不成立，应该保留什么、停止什么、下一步最小工作是什么？

目的不是通过加大权重制造轨迹变化，也不是把“能运行”包装成“有收益”。需要区分：

- **工程接入正确**：实现、时间、身份、数值与 OFF 回归成立。
- **经验不退化**：在冻结配置和已测数据范围内，ON 满足预先定义的精度、稳定性和开销标准。
- **统计一致性**：噪声及相关性模型可信，并有对应的一致性证据。
- **融合收益**：相比匹配 OFF 基线获得可重复的有效改善。

四种结论不能相互替代。不能因为后两种尚未成立，就重复已完成的纯结构整理；也不能因为前两种成立，就声称后两种成立。

## 4. 验收标准：运行 ON 前冻结

以下数值是**本轮建议的工程容限**，不是理论定理，也不是已获得的统计证据。优先遵循已有、明确且适用于本轮的仓库验收合同；没有合同则采用下述默认值。

在首个新 ON 结果产生前写入 acceptance.yaml 或等价机器可读文件，记录来源与版本。不得看到结果后放宽；更改容限必须标记为新的实验合同并保留原结果。

### 4.1 OFF 等价：硬要求

目的：把架构扩展、诊断和修复的影响与融合影响分开。

- 对既有确定性回归序列，主状态、完整主 P、Observer 完整 x/P_R、生命周期/readiness 与已有冻结基线按既有规范精确一致。
- 新日志字段可排除 wall time 等非确定性数据，但须明确字段列表，不能排除估计结果。
- 不用模糊容差把本应精确一致的 OFF 变成“近似一致”。
- 若 seed 或 Observer 均值意外改变，先定位原因，停止用该版本开展 ON 验收。
- 纯浮点环境差异导致旧基线不可比时，建立有原因记录的匹配 OFF 基线；不能宣称原精确回归通过。

### 4.2 数值与接入正确性：硬要求

目的：防止“指标正常但更新对象或模型已经错误”。

- 无新增崩溃、发散、非有限状态、非法协方差、时间倒退或异常 reset。
- Jacobian 按原生 JPL 注入约定做有限差分核对；覆盖不同姿态与位姿，记录步长及误差量级。
- 当前 residual 与 FEJ Jacobian 的约定一致；正确映射状态列，不混用 body/world 或 camera/IMU。
- 时间、epoch、代次、anchor、clone、receipt 一次性消费一致。
- 首次主状态/P差异对应一次真实辅助更新；不能把 ready 或 eligible 当作 applied。
- 联合协方差 PSD、创新 S 的有效秩及可求解性有依据；沿用有来源的数值容限。
- 新统计模块失效时应明确拒绝辅助融合，不污染原始视觉路径。

### 4.3 经验精度不退化：每条序列分别判定

目的：检验 ON 是否在允许的工程差异内；不是要求必须有明显收益。

对于误差指标 M，定义：

$$
\Delta M=M_{\mathrm{ON}}-M_{\mathrm{OFF}}.
$$

建议默认要求：

| 指标 | 允许的恶化上限 |
| --- | --- |
| 全程 ATE RMSE | max(0.5% × OFF，0.001 m) |
| 1秒与5秒 RPE 平移 RMSE | max(0.5% × OFF，0.001 m) |
| 1秒与5秒 RPE 旋转 RMSE | max(0.5% × OFF，0.01°) |
| 速度 RMSE（有可信速度参考时） | max(0.5% × OFF，0.005 m/s) |
| 预先冻结的退化/恢复区间：对应 RMSE | max(2% × OFF，对应全程绝对容限的2倍) |

- 指标定义、轨迹对齐自由度、GT坐标变换、时间关联、采样率、评价区间必须相同。
- 不使用不同的尺度对齐掩盖双目惯性系统尺度变化。
- 不能用一条序列的改善抵消另一条序列超限；按模式、按序列分别报告。
- 不能从 ON 曲线挑出有利时段。局部区间按 OFF/已有诊断在新 ON 前冻结。
- 无可信速度 GT 时，速度准确性标 NOT_EVALUATED，不把重建/差分伪参考当独立真值。
- 这些容限允许微小恶化，结论应称“满足工程容限”，不能称“严格没有任何退化”。

### 4.4 稳定性与开销

目的：确保功能不会以运行可靠性或实时性为代价。

- 新增失败、发散、异常 reset 为0；数据缺段和未完成回放不能算完整成功。
- 每帧处理耗时 p95 相对匹配 OFF 增长不超过5%；并行回放产生的资源竞争应剔除或重测。
- 峰值内存相对匹配 OFF 增长不超过10%；同时报告绝对值。
- 不增加相机积压、丢帧或时序滞后；不能仅靠降低回放倍率让实时性通过。
- shadow 的重诊断开销与最终候选生产路径开销分开报告。
- 环境不足以测量时明确标 NOT_EVALUATED，不能仅凭构建成功判定实时性通过。

### 4.5 统计一致性与范围

目的：限定结论边界，避免“工程容限通过”被写成数学一致性证明。

- 只有 P/R/N 的统计含义、共享输入依赖和相关性处理成立，才可使用相应 NIS/NEES 概率验收。
- χ² 单帧门控通过，不等于时序一致性通过。
- 不能把确定性重复回放当独立随机样本计算置信区间。
- NEES 的状态子块、真值、规范自由度和对齐方式必须明确；不对不可观绝对自由度机械套用测试。
- 没有独立试验或合适统计模型时，报告描述性分布和缺口，结论保持 NOT_ACHIEVED / NOT_EVALUATED。
- 不宣称有限测试能够保证任意场景不退化。

## 5. 阶段 A：冻结身份与复用证据

**目的**：避免分支混合、重复长回放和使用不匹配的结果。

行动：

1. 核对仓库、AGENTS.md、当前分支、dirty 状态和已有验收合同。
2. 建立提交/配置/数据/运行环境清单；找出当前最合适的冻结基线，不盲目从过期分支开始。
3. 核对历史报告与原始日志是否匹配，建立证据索引。
4. 实测一个完整回放的耗时、资源占用和可用数据，再安排运行矩阵。
5. 冻结 acceptance、评价脚本及局部区间。

通过：每个结果能追溯到唯一配置与代码，后续可比。缺失项有明确补齐计划。

## 6. 阶段 B：G/V 现有接入与更新作用审计

**目的**：判断“没收益”是没有更新、更新很弱、方向不对、重复信息，还是收益被整体指标隐藏。

优先复用已有完整诊断，逐模式统计：

- available、valid、ready、eligible、gate accepted、joint applied，及每类拒绝原因。
- r_G/r_V、R、S、NIS、鲁棒权重（若启用）、观测供给和成熟度。
- delta_x=Kr 的姿态/速度/位置/bias 分块，及对应 P 的变化。
- 主误差增长区间的实际覆盖率、更新前后局部误差与恢复时延。
- 同样现象是否重复出现，而不是依据单帧峰值下结论。
- 当前独立噪声近似、G/V之间及与视觉之间的未知相关性。

允许的结论：无更新、作用极弱、局部有作用但全局不显著、方向不稳定、经验超限、证据不足。

决策：

- 有明确接入错误：最小修复，重新 OFF，再进入对照。
- 正确运行且满足工程容限但无收益：保留实验能力，默认关闭；无需为了获得变化继续调大信任。
- ON 有退化：停该模式，保存原因，不用另一模式掩盖。
- G 没有新优势证据：维持关闭；V 可以独立判断。

## 7. 阶段 C：Observer 统计模型与观测来源审计

**目的**：解决“辅助估计能否合法回灌给产生它的主滤波器”。

至少完成：

1. 区分 Riccati P_R 与 Sigma_L=Cov(estimate−true)，审计当前实际离散映射。
2. 梳理 seed 对主历史位姿、bearing、外参和时间标定的依赖。
3. 推导主状态、Observer、anchor 与共享输入的联合误差传播。
4. 同一帧 bearing 在 Observer Euler 子步中重复使用，不视为独立测量。
5. slot 置换、birth/retire、reset、clone扩增/边缘化、anchor替换保留正确误差映射。
6. 主视觉更新和误差注入之后，审计 Observer 与主状态交叉块如何变化。
7. 建立输入来源账本，记录历史 bearing 在 seed、Observer、MSCKF等路径的使用。

优先完成只读 shadow：不改变估计均值，记录联合块的有效性、秩和开销。

### 7.2 实验统计合同与判定边界

先写 landmark_correlation/experiment_contract.yaml，至少冻结：

- 误差定义：主状态 true-minus-estimate；Observer/seed/anchor 为 estimate-minus-true；统一 JPL 注入、坐标和 FEJ 评价点。
- 所有随机量的来源ID、时间、单位、噪声模型、相关性及初始化；无法得到的项标 UNKNOWN，不自动置零。
- 主状态/Observer/anchor/仍复用输入的联合状态布局，及每个生命周期事件的矩阵映射。
- 小系统的独立参考计算路径、矩阵归一化、数值比较与有效秩容限。不能使用被测实现自己产生的结果作为唯一真值。
- LC-06 的零噪声、独立来源、共享IMU/bias、共享bearing、seed回灌、完全重复信息和近秩亏场景；每种场景都保存通过/失败预期。
- Monte Carlo先用不少于1000次独立抽样的低成本参考片段。抽样数、随机seed、显著性水平和多重检验处理在看结果前冻结；精度不足时按预设规则增加抽样，不放宽阈值。
- 采用样本协方差/交叉协方差的可解释置信区间或独立bootstrap方案；测试必须有能力识别预设大小的相关性错误。仅“不显著拒绝”而检验功效不足时，标 INCONCLUSIVE。
- 独立随机抽样与同一真实序列的确定性重复严格分开；不能把多次相同回放当作Monte Carlo样本。
- 除线性高斯参考外，真实seed/Observer的局部非线性片段按多个冻结扰动幅度评价；记录线性化失效，不通过选一个有利幅度掩盖问题。

受控真实输入扰动优先作为离线实现核对：使用同一源噪声驱动所有消费路径。扰动后重新运行了错误映射并没有提供独立真实landmark误差；真实点真值缺失时，Sigma_L 的实测校准仍标 NOT_EVALUATED。EuRoC 位姿GT或由共享bearing重新三角化的点不等于独立landmark真值。

LC-05 中的“交叉块置零”只存在于离线对照函数，禁止成为生产或实验ON的静默fallback。关闭未知相关项与原始模型可能产生不兼容的联合分布，必须记录，不能用裁负特征值、ridge或调大R让它看起来成立。

### 7.3 最小运行矩阵与自动推进

目的：优先把理论依赖落实为证据，避免机械安排大量整段回放。

1. LC-01～LC-04先跑小系统、数学/身份测试；LC-06受控参考可以并行推进。
2. 基本块成立后执行LC-05；其结论用于确定LC-07需要捕获哪些字段，不能用于按GT调权重。
3. 当前代码和输入来源可用时，V2_02/V2_03各一次完整LC-07 shadow；若缓存缺联合误差/来源字段，不能宣称缓存已经验证新模型。
4. 为新统计实现验证OFF精确复现与确定性：匹配已有可信OFF和同配置重复shadow；有直接可比的完整证据可复用。无法复用时每条序列补一次完整重复。
5. LC-08优先复用符合预冻结合同的观测；缺真正未消费观测时先建立数据拆分。留出观测不得进入其预测前的seed、Observer或比较几何基线；不得把修改观测消费后的实验当作原生产OFF。
6. 若真实路径超预算，先减少shadow记录频率或离线存储量，保留完整必要传播；不能通过丢交叉块假装完成模型。
7. LC-01～LC-04存在关键UNKNOWN时，停止受影响真实ON路径；仍完成可行的小系统核对、来源审计和具体缺口定位。不得只写一份设计文档就将全部LC实验标PASS。
8. 有证明适用的保守替代时，单独登记模型合同、理论依据和对应校准实验；不能借此绕过来源与重复信息检查。

每个LC项使用 PASS / FAIL / BLOCKED / INCONCLUSIVE / NOT_EVALUATED，并记录作用范围。数学正确、合成校准、真实路径可运行、真实统计校准和新增信息分别判断。即使LC-01～LC-07通过，LC-08不足仍可停止landmark ON；即使允许试验ON，也不能预先声称统计一致性或轨迹收益。

## 8. 阶段 D：Landmark GO / STOP 判定

**目的**：在增加新更新之前，确定既有三维预测包含可用增量信息，且重复信息不会造成过度自信。

残差候选：

$$
r_L=\hat\ell_t-R_t(R_a^T\hat\ell_a+p_a-p_t).
$$

令 A=R_t R_a^T，e_a/e_t 为辅助点 estimate−true：

$$
\nu_L=e_t-Ae_a,
$$

$$
R_L=\Sigma_{tt}+A\Sigma_{aa}A^T-A\Sigma_{at}-\Sigma_{ta}A^T,
\qquad
N_L=C_{xt}-C_{xa}A^T.
$$

联合残差 r=H delta_x+nu、N=Cov(delta_x,nu)：

$$
S=HPH^T+R+HN+N^TH^T,\quad
B=PH^T+N,\quad K=BS^{-1},\quad P^+=P-BS^{-1}B^T.
$$

GO 必须同时满足：

- 阶段 C-L 的实验矩阵已经实际执行：关键项不存在FAIL/BLOCKED，INCONCLUSIVE有明确范围限制；不能以设计文档代替实验。
- 两时刻点身份、物理时间、活跃 anchor、FEJ 和 Jacobian 正确。
- R/N 及与视觉的交叉块可获取，或有明确适用范围且经验证的保守替代。
- 联合协方差、有效秩及重复信息反例通过数学核对。
- seed 的主状态信息依赖未被删除；没有伪造外部地图独立性。
- 有冻结的数据合同检验未消费观测预测或其他可识别信息增量；历史几何对照不能被撤掉。
- 预算可接受，OFF 精确复现。

“降低 R”“允许相关开关”“只删除同帧同ID视觉行”都不构成相关性闭合方案。CI 或相关性界可以研究，但必须证明适用于当前相对约束及规范自由度，不能直接套6D位姿CI。

STOP 时保留 shadow，交付原因、缺失矩阵/依赖、最小后续扩展；不要继续空转或运行不满足前提的 ON。

## 9. 阶段 E：最小 ON 对照与扩展覆盖

**目的**：用尽可能少但有效的完整运行得到限定范围的结论。

顺序：

1. 先用已有 V2_02/V2_03 结果做匹配合同的复核，不无理由重跑全部历史。
2. 若修改了在线路径或现有证据缺失，运行对应 OFF 重复及候选 ON 重复。
3. 区分 G-only、V-only、GV；每种模式独立结论，未选候选的无效模式可停止扩展。
4. 在已有两条序列上满足标准后，补至少两条其他序列：在新 ON 前根据 OFF 与可用数据确定，一条常规、一条视觉退化/恢复或更困难场景。
5. 每条序列、每种候选模式至少获得完整匹配 OFF/ON；确定性复核按合同补足。
6. Landmark 只有阶段 D GO 后才加入，先独立 landmark-only；不要同时改变 V 确认门限或主 SLAM 状态。
7. 编译、相关测试、数学检查和精度评价均完整记录。

优先级是完成有效对照，不是最大化运行次数。多个回放若会争抢 CPU/内存影响吞吐和时序，顺序执行；分析任务仍可并行。

缺少扩展序列时，允许形成“仅 V2_02/V2_03 的经验结论”，明确覆盖不足，不颁发泛化通过。

遇到问题根据原因调整后续实验；任何新源码修复都重新校验受影响的 OFF 与 ON，不能把修复前后的结果混为同一组。

## 10. 多 agent 执行建议

**目的**：并行解除独立疑问，不让多个 agent 同时修改同一融合路径。

| Agent | 主要职责 | 交付 |
| --- | --- | --- |
| 主 agent | 冻结合同、分支管理、集成、排程与最终判定 | manifest、acceptance、decision、最终报告 |
| G/V 审计 agent | 只读日志、更新分块、局部退化定位 | gv_audit、指标与曲线、最小修复建议 |
| Observer agent | LC-01/02/06：实际离散误差、seed、共享噪声与随机扰动校准 | covariance_design、联合传播、Monte Carlo证据 |
| Landmark agent | LC-03/04/05/08：anchor、消元、近似对照与增量信息 | 相关性实验结果、landmark_go_stop |
| 验收执行 agent | 构建、回归、运行矩阵、结果完整性 | build/test/replay记录及统一指标 |

资源不足可合并角色；多 agent 不代表必须并行跑多个 ROS 回放。

- 每个写代码的 agent 使用独立 worktree；明确拥有的文件和允许改动范围。
- acceptance 由主 agent 单点冻结；数学模型变更先同步相关角色。
- 子 agent 不自行修改生产参数、不改变验收阈值、不宣称最终通过。
- 由主 agent 集成独立提交，再对集成版本构建和回归。
- 手动开的多个会话通过共享进度文件与提交哈希交接；不能假定它们自动共享上下文。
- 不因“今天完成”省略依赖；今天优先收口 G/V 审计和 landmark GO/STOP，完整 ON 验收取决于模型与实际运行预算。

## 11. 最终结论格式与停止规则

分别给出：

| 判定项 | 允许状态 |
| --- | --- |
| OFF 工程等价 | PASS / FAIL / BLOCKED |
| G-only 经验不退化 | PASS_WITHIN_SCOPE / FAIL / NOT_EVALUATED |
| V-only 经验不退化 | PASS_WITHIN_SCOPE / FAIL / NOT_EVALUATED |
| GV 经验不退化 | PASS_WITHIN_SCOPE / FAIL / NOT_EVALUATED |
| Landmark 相关性实验 | LC-01～LC-08逐项 PASS / FAIL / BLOCKED / INCONCLUSIVE / NOT_EVALUATED |
| Landmark 前提 | GO / STOP_WITH_REASON |
| Landmark ON 经验不退化 | PASS_WITHIN_SCOPE / FAIL / NOT_IMPLEMENTED |
| 统计一致性 | ACHIEVED_WITH_ASSUMPTIONS / NOT_ACHIEVED / NOT_EVALUATED |
| 融合收益 | DEMONSTRATED_WITHIN_SCOPE / NOT_DEMONSTRATED |

- “任务执行完成”可以包含清楚且有证据的 STOP，但不能写成“全部融合验收通过”。
- BLOCKED/STOP 必须指出具体技术依赖或数据/环境缺口，不能仅写“时间不够”。
- 一旦重复信息导致零有效增量、模型无效或数值错误，停止对应 ON；继续其他独立且有效的工作。
- 不要求用户逐阶段签字；常规判断在冻结合同内自行完成。
- 外部权限、不可访问数据或与用户目标冲突的范围变化，明确报告，不能制造成功证据。
- R4 未闭合项只在对应证据满足时更新，不能因为工程回归通过而统一清零。
