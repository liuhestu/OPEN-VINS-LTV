## 3. 输入充分性与缺口

旧合成产物有每个200Hz状态、每相机校正前后完整矩阵、逐帧事件、冻结IMU/bearing/位姿先验和标签分离文件，足以定位上述最早失效。此次未加载巨大完整P或做谱分解，也未重算旧矩阵。

已有保存数据的不足：相机before记录在生命周期与种子写入之前，after记录在全部子步之后；没有现场保存“单次种子刚写完但尚未校正”的快照，也没有新/旧路标分项校正贡献。这些不能用before/after简单相减冒充。建议在本轮新短harness增加三个明确事务位置，并以既有单测核对P旧子块不变。真实EuRoC启动/短断档窗口尚由主agent从manifest指定；不能拿合成adapter以外的harness事件等同已验证真实桥接时序。

## 4. 最小状态机建议（须主协议冻结后实施）

保留一个持久observer；首轮不引入第二observer，不默认主VIO复制，不调Q/V/P。显式区分收集历史的时钟与正在估计的状态时刻。

1. **COLLECTING**：可靠集合不足时只维护有限历史/IMU缓存及receipt；没有当前估计就raw=null、observer_valid=false。不能调用旧pause反复清空候选历史。有效候选集合达到固定规模/几何合同后才能进入一次原子bootstrap。
2. **BOOTSTRAPPING**：在真实当前时刻构建一整份x/P/slot/游标并一次写新种子，记录bootstrap来源。零v/η默认保留用于最小H1对照；不把启动前空池积分当可靠状态。种子与manager入槽事务只能在core成功后提交，失败不得形成“管理器已准入、核心无槽”的半完成状态。
3. **TRACKING**：至少需要有效校正次数+连续真实观测+observer级健康，而非单纯驻留时长。G/V独立ready，保留共同raw支持。新点不挤走可靠旧点，不复制丢失bearing。
4. **DEGRADED**：空/非法输入最多两个相机包内撤销ready；短缺测继续有限传播，绝不把计数一补齐当恢复完成。建议首轮预登记0.20 s缺乏最少规模进入DEGRADED、1.0 s无充分集合进入DORMANT，数字属于待冻结候选参数，不是已验证阈值。
5. **DORMANT/RECOVERING**：不发布带当前时间戳的旧raw；history继续。可靠几何重新到来且距上次质量bootstrap≥30 s时允许原子重建，物理时序故障另计，不能伪装故障绕过冷却。恢复需连续确认，不按输入脚本阶段切换。

首轮应分别对照“只延迟启动”和“同raw新增readiness”；二者可能各自失败，仍能给出下一步证据。若明确证明零v/η启动是剩余瓶颈，才进入goal允许的 `POSE_AIDED_BOOTSTRAP`：每episode至多一次，30 s质量重建间隔，来源日志完整，并强制评价写入5秒之后及≥20秒无再次写入段。

## 5. 有界生命周期：当前缺陷与可部署约束

当前history样本有256候选/1s窗口，IMU缓存有10s边界；但以下结构按总遇到ID增长：manager `landmarks_`和`retired_`、adapter `ids_`、core `admitted_ids_`。每帧遍历全部landmarks计算累计机会/准入也随时长增长。日志过滤掉已退休点并不能降低内存。

单纯TTL删除tombstone会允许同epoch旧ID重新seed，是错误修复。对于任意无序无限ID，有限内存不可能同时精确记住所有曾准入身份；必须声明可验证的来源契约或选择保守拒绝策略。

本前端 `TrackKLT.cpp`在新检测时使用`++currid`（TrackBase中atomic计数），建议显式的新路径ID合同：

- 保留当前候选/ACTIVE/COASTING的有限精确映射；保留一个已见ID高水位与有限当帧新ID集合。
- 先整批识别本帧新ID，再推进高水位；仍在候选或活动映射中的老ID继续合法。
- 不在精确映射、且≤此前高水位的ID一律以`old_identity_outside_window`拒绝，不能重新入槽；超容量当帧新ID记录拒绝后不再无限占内存。这会保守拒绝极晚出现的旧ID，必须报告覆盖损失，不能悄悄恢复它。
- core控制模式同样用受控单调birth generation/高水位替代无限admitted集合，frame内批量验证，避免风险排序不是ID排序导致错误拒绝；原旧路径不受影响。
- adapter只保留当前候选/活动需要的映射；core ID单调计数不回收值，已退休ID检测由高水位合同负责；integer溢出是明确故障，不静默回绕。
- 累计birth/opportunity/admitted/retired/TTL计数以标量保存；完整历史写事件日志。计数必须在状态迁移时更新，不能每帧遍历总历史。
- frontend reset与observer质量episode必须区分；若同一前端ID跨质量bootstrap可再次初始化，必须显式更换observer epoch且一次写入规则按该epoch审计，不能无日志隐藏重写。

需新增单测：同帧无序新ID、低ID仍活动、高水位以下离场再出现、超容量后再出现、不同epoch同名ID、10分钟高birth率容量上界、计数与事件重建一致。若真实桥接不能证明单调来源，先保持拒绝/报告不支持，不假设未知地图ID满足此合同。

## 6. 有界身份补充：不擅自假设任意输入ID单调

以上高水位策略必须是**明确声明并测试的前端合同**，不能默认为所有缓存、MSCKF地图点和未来外部tracker成立。低ID长寿命点只要仍在有限活动/候选映射，就不能因高水位上升被误删。含重识别或非单调全局ID的输入，直接高水位策略会保守拒绝大量合法新点，需先作为不支持或独立对照报告。

若主桥接暂时无法证明单调合同，可选一个有限、永不清位的epoch内退役身份Bloom集合：只允许假阳性（额外拒绝），禁止假阴性（重复seed）；精确候选/ACTIVE映射优先于Bloom检查。固定bit容量和hash在配置/版本中冻结，日志记录占用和由此拒绝的数量；接近饱和时明确pool不足，不通过静默清空或质量reset清位来恢复覆盖。这个方案有可解释的覆盖损失，不能声称精确历史身份集合。每个observer epoch清空须有合法启动/恢复事务，不把内存清理伪装成新epoch。主任务是否采用，应由开发覆盖和10分钟资源测试决定。

无论哪种策略，都必须将“物理tracker epoch”“observer bootstrap episode”和“缓存事件sequence”分别定义；一次seed合同明确绑定哪一epoch。完整从未准入TTL与已准入退休事件由日志保存，在线只留有限活体映射和常数计数。事务失败不得增加已seed计数或提交身份阻止记录。
